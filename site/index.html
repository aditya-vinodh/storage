The idea

Agents make things. People need to see them.

An agent fixes the checkout page and takes a screenshot. Where does it go? Today it ends up in a temp folder, a pasted image, or a bucket nobody cleans. Storage gives it a home.

Store

Agents put files into collections through the CLI or MCP. Every write is a new version, and nothing is public by default.

“Save a screenshot of the new checkout to the PR.”

Share

Give access to a teammate, your Google Workspace domain, a GitHub org or team, or a review bot. Or send a link that expires.

“Share this with the design team for a week.”

Clean up

Tie a collection to its pull request. Rules like “delete 7 days after merge” tidy up for you, with a grace period to restore.

“Keep the last 3 versions of each report.”
Get started

Three commands to your first artifact.

Install the CLI, sign in to your server, and hand your agent the tools.

1

Install the CLI

$npm install -g @storage/cli

The npm package isn't published yet. Until it is, build from source with the first-run guide.

2

Sign in

$storage login --server https://storage.your-company.com

Opens your browser to sign in with Google. Running your own server? It's one container with docker compose.

3

Connect your agent

$claude mcp add storage -- storage mcp

Any MCP client works. Point it at the command storage mcp, or at your server's hosted endpoint, /mcp.

Then ask your agent: “Take a screenshot of the checkout page and store it on my pull request.” It lands in gh-pr:acme/web#482, shared with whoever can see the PR.

Works with

Your agents, your servers.

Open source and self-hosted first: one container, Postgres or SQLite, and any S3-compatible bucket.
